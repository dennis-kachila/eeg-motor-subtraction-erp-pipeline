# Second Milestone Folder Structure Guide

## Purpose of this document

This guide explains the purpose of the folders and important files inside the `second_milestone` folder in plain language.

It is meant to answer questions like:

- Which folders contain the actual code?
- Which folders contain input data?
- Which folders are generated when the pipeline runs?
- Which files are for running, configuring, or reviewing the pipeline?

## Big picture

The `second_milestone` folder is being used as a self-contained working area for:

1. Reviewing the pipeline code
2. Running the pipeline on the sample BDF files
3. Saving outputs locally so results can be compared before and after fixes

The folder contains three main kinds of content:

- Source code and configuration
- Input sample data
- Generated runtime/output folders

## Top-level structure

### `EEG_Processing/`

This is the main code folder for the milestone.

It contains the MATLAB scripts that implement the EEG pipeline stages and the helper utilities they depend on.

Subfolders inside it represent the main processing steps:

- `shared_utilities/`: common helper functions used across the whole pipeline
- `eeglab_preproc/`: Step 1 preprocessing from raw BDF files
- `eeglab_artifact_rejection/`: Step 2 automated artifact rejection
- `eeglab_ICA/`: Step 3 ICA decomposition
- `eeglab_IC_rejection/`: Step 4 IC classification and rejection
- `eeglab_post_ICA/`: Step 5 post-ICA cleanup
- `eeglab_epochs/`: Step 6 epoch extraction by condition and block
- `eeglab_ERP_analysis/`: Step 7 ERP computation, comparison, and plotting
- `Pipelines/`: stored pipeline configuration versions

### `Full_Sample_Dataset/`

This contains the sample raw EEG files provided for milestone testing.

Current files:

- `sub-01_ses-01_task-no-action_eeg.bdf`
- `sub-01_ses-02_task-action_eeg.bdf`

These are the raw inputs for the pipeline.

### `sourcedata/`

This is a runtime input folder created so the code can run using the folder structure it expects.

Why it exists:

- The MATLAB code expects raw data to live under `sourcedata/sub-XX/eeg/`
- The sample BDF files from `Full_Sample_Dataset/` were copied here to make the pipeline runnable without changing the raw files themselves

Current example:

- `sourcedata/sub-01/eeg/`

This folder currently contains the same two sample BDF files used for testing.

### `derivatives/`

This is a runtime output folder.

It stores files generated by the pipeline while it runs.

Current subfolders include:

- `eeglab_preproc/`: outputs from Step 1 preprocessing
- `eeglab_ICA/`: outputs from Step 3 ICA
- `eeglab_ICrej/`: outputs from Step 4 IC rejection
- `eeglab_post_ICA/`: outputs from Step 5 post-ICA processing

Important note:

- This folder is not original source code
- It is where processed EEG files are saved so before-versus-after comparisons can be made later

### `code/`

This is a compatibility folder created to satisfy the path conventions expected by the milestone scripts.

Why it exists:

- Some scripts assume a folder layout like `code/shared_utilities`, `code/eeglab_preproc`, and `code/Pipelines`
- The actual milestone code lives in `EEG_Processing/`
- This `code/` folder mirrors that structure so the pipeline can run without rewriting everything first

In practice, this folder acts like a path bridge between the expected layout and the actual milestone layout.

### `second_milestone_instructions.md`

This is the milestone brief.

It explains the review goal:

- Full end-to-end review of the EEG preprocessing and analysis pipeline
- From raw BDF input through final N1 and P2 ERP outputs
- Covering code correctness and methodology

This file is the main instruction file for the milestone work.

### `run_full_pipeline_baseline.m`

This is a helper runner added to execute the pipeline locally from inside `second_milestone`.

Purpose:

- Run the pipeline using the sample data inside the milestone workspace
- Save outputs under `second_milestone/derivatives/`
- Preserve a baseline output set before code fixes are applied

This is not an original research script. It is a workspace-specific execution helper.

### `Step_1_to_5_Code_Review_Findings.md`

This is the review report already created for the code in Steps 1 to 5.

Purpose:

- Document the issues found before fixing them
- Serve as the baseline review record

## Inside `EEG_Processing/`

### `shared_utilities/`

This folder contains support functions used by many steps.

Think of this as the infrastructure layer of the pipeline.

Important files:

- `GetFilePathsAndInitializeToolboxes.m`: decides where input, output, and pipeline folders are
- `GetConfig.m`: builds the configuration for a given subject, session, and stage
- `RunMyScripts.m`: central controller that loops over subjects and sessions
- `run_pipeline.m`: top-level runner for multiple steps
- `CreateAndModifyPipelineAsset.m`: creates or updates saved pipeline parameter sets
- `ApplyFilters.m`: applies high-pass and low-pass filters
- `Rereference.m`: rereferences EEG to mastoids or another reference
- `BaselineCorrect.m`: applies baseline correction when requested
- `SaveMyData.m`: saves EEGLAB `.set` datasets
- `GetChannelIndices.m`: looks up channels by name
- `GetFileBySubstring.m`: finds files based on partial name matching

If you want to understand how the whole pipeline is wired together, this is usually the first folder to inspect.

### `Pipelines/`

This folder stores versioned processing settings.

Each pipeline is saved as a `.mat` configuration file, so the same preprocessing choices can be reused consistently.

Example:

- `Pipelines/Pipeline_003/Pipeline_003_version001.mat`
- `Pipelines/Pipeline_003/Pipeline_003_version002.mat`
- `Pipelines/Pipeline_003/Pipeline_003_version003.mat`
- `Pipelines/Pipeline_003/Pipeline_003_version004.mat`

What these files represent:

- filter settings
- rereferencing settings
- artifact rejection thresholds
- ICA settings
- IC rejection thresholds
- post-ICA settings

This folder is the parameter history of the pipeline.

### `eeglab_preproc/`

This is Step 1 of the pipeline.

Purpose:

- load raw BDF files
- label events
- load channel locations
- remove dead EOG channels
- rereference
- filter
- downsample
- save continuous preprocessed datasets

Important files:

- `PrepareData_1_Preprocessing.m`: main preprocessing function
- `label_events.m`: converts raw event codes into readable labels like `Tone_Low`, `Key_Press`, `Main_Block`
- `run_preproc.m`: standalone runner for Step 1

### `eeglab_artifact_rejection/`

This is Step 2.

Purpose:

- use automated cleaning to remove bad segments and channels
- preserve important block markers if cleaning would otherwise delete them

Important files:

- `PrepareData_2_AutomaticArtifactRejection.m`: main artifact rejection function
- `run_artifact_rejection.m`: standalone runner for Step 2

### `eeglab_ICA/`

This is Step 3.

Purpose:

- run ICA on cleaned continuous data
- decompose the EEG into independent components
- prepare for automatic artifact component rejection

Important files:

- `PrepareData_3_RunICA.m`: main ICA function
- `run_ica.m`: standalone runner for Step 3

This is usually one of the slowest stages.

### `eeglab_IC_rejection/`

This is Step 4.

Purpose:

- classify ICA components using ICLabel
- reject components likely to be eye, muscle, line noise, or other artifacts

Important files:

- `PrepareData_4_RejectICs.m`: main IC rejection function
- `run_rejectIC.m`: standalone runner for Step 4

### `eeglab_post_ICA/`

This is Step 5.

Purpose:

- perform final cleanup after IC rejection
- optionally interpolate removed channels
- optionally reject bad epochs if data is epoched
- apply final rereference

Important files:

- `PrepareData_5_PostICAProcessing.m`: main post-ICA function
- `run_post_ICA.m`: standalone runner for Step 5

### `eeglab_epochs/`

This is Step 6.

Purpose:

- detect action versus no-action conditions
- split data into adaptation and main blocks
- create epochs aligned to tones or keypresses

Examples of files here:

- `PrepareData_6_ExtractConditions.m`
- `extract_action_condition.m`
- `extract_noaction_condition.m`

### `eeglab_ERP_analysis/`

This is Step 7.

Purpose:

- compute ERP measures such as N1 and P2
- perform motor subtraction where needed
- create waveform and scalp-map plots
- save subject ERP result files

Examples of files here:

- `PrepareData_7_ComputeERPs.m`
- `compute_N1_P2.m`
- `subtract_motor_and_compute_difference.m`
- plotting scripts

## How data moves through the folder

This is the simplest way to think about the pipeline flow:

1. Raw BDF files begin in `Full_Sample_Dataset/`
2. Those files are staged into `sourcedata/sub-01/eeg/`
3. Step 1 writes preprocessed datasets into `derivatives/eeglab_preproc/sub-01/`
4. Step 2 writes cleaned datasets into the next derivatives folder
5. Step 3 writes ICA datasets
6. Step 4 writes IC-rejected datasets
7. Step 5 writes post-ICA datasets
8. Step 6 would write epoched datasets
9. Step 7 would write ERP result files and figures

So the folder structure is designed to preserve each stage output separately instead of overwriting everything in one place.

## Which folders are original vs generated

These are the main folders/files that represent the milestone materials:

## Short glossary

- `.bdf`: raw EEG recording file
- `.set`: EEGLAB dataset file
- `.fdt`: binary data file used with `.set`
- `sourcedata`: raw inputs prepared in the structure expected by the pipeline
- `derivatives`: processed outputs created by pipeline stages
- `Pipeline_003_version00X.mat`: saved configuration version for a processing pipeline
